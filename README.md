# AI 聊天重命名助手 V0.4

Edge / Chrome 120及以上版本的浏览器扩展。根据所选聊天的正文，为一批历史聊天生成更明确的中文标题，再预览、修改并批量写回。不会逐个打开聊天页面点击菜单。

当前支持 **ChatGPT** 与 **DeepSeek** 两个平台。两者共用同一套命名规则、模型后端和恢复记录结构，平台差异隔离在 `adapters/` 下。

这是可加载的扩展源码，不是截图原型。**尚未在你的真实账号上写入标题。**V0.2已用两段虚构聊天实测本机 Codex CLI 的命名请求；真实网页接口仍需加载扩展、连接你的 ChatGPT 登录状态后验证。网页内部接口并非 OpenAI 公开稳定 API，可能因改版、账号权限、验证或限流而不可用；工具遇到这些情况会停止。

## 安装扩展

1. 在 Edge 打开 `edge://extensions`（Chrome 对应 `chrome://extensions`）。
2. 开启页面上的“开发人员模式”，点击“加载解压缩的扩展”。
3. 选择本目录 `chatgpt-renamer`。如果使用交付 ZIP，先解压，再选择里面有 `manifest.json` 的文件夹。
4. V0.4 新增了 `chat.deepseek.com` 站点权限，升级后需在扩展管理页点击本扩展的“重新加载”，浏览器询问新权限时选择允许。
5. 打开并登录 `https://chatgpt.com` 或 `https://chat.deepseek.com`，点击浏览器扩展图标；操作页会自动带入当前平台。

扩展会打开自己的操作页，你仍然在原来的 ChatGPT 网页聊天。不读取浏览器 Cookie 数据库，也不要求你复制登录 Token。

## 一次确认，自动处理全部所选

1. 扫描聊天，勾选需要整理的记录。
2. 在“模型与命名规则”中使用默认规则，或直接编辑规则文字。规则修改后自动保存，不必重新授权模型连接；“恢复默认规则”可以切回默认内容。
3. 保留“跳过当前规则已处理”的勾选，点击“一键自动重命名”。
4. 开始前确认一次聊天范围和规则，之后自动执行“每5条生成一批 → 逐条写回并核对 → 下一批”，不再每5条弹出确认。

聊天列表分为“待处理”和“已处理”两个视图。已处理的归类包括旧版成功记录，不会因此推断旧记录使用的是当前命名规则；可切到“已处理”视图选择并恢复。批量按钮只作用于当前视图中经过筛选后显示且选中的聊天。

单条聊天没有可识别的文字、已删除或标题冲突时，记录该条错误并继续其他聊天；未完成项目可在待处理视图查看。账号失效、限流、网络/模型批次失败或写入结果未知时，整批暂停，按提示核对或重试，避免重复写入。

例如选择100条，只需在开始时确认一次，内部会分成20批顺序处理。运行时保留助手页面和本机服务；可以点击“停止”。单条标题冲突时跳过该条，账号失效、限流、模型批次失败或写入结果不明时暂停，保留已经完成的记录。

“仅生成预览”和“预览并应用”仍保留，适合希望先检查标题的情况。免 Key 复制/导入模式需要手动把任务交给 AI，不具备连续自动生成能力。

## 按规则记录完成状态

- 标记由**账号/工作区、聊天编号、命名规则**共同确定，保存在本机扩展日志中，不往 ChatGPT 标题里加标签。
- 相同规则下，已成功写回并重新读取确认的聊天会自动跳过，不再次调用模型。重新扫描、刷新页面、重启浏览器后仍保留。
- 改成另一套规则时，同一批聊天可以再处理；切回之前的规则时，之前的完成记录仍有效。
- 规则标识只根据规则文字生成，不因为切换模型或后端而变化。首尾空白、连续空格或换行的格式差异不会创建另一套规则。
- 仅生成建议不算完成。执行失败、未确认写回、未处理到的聊天不会标记成功。模型生成的标题与当前标题一致时，重新读取核对后标记“已符合规则”，无需重复写入。
- 结果未知的写入需要先点击“核对未完成操作”。核对成功后补齐完成标记；确认没有应用则可继续，避免盲目重复写入。
- 恢复某条改名记录成功后，撤销该记录的完成标记。其他规则或更早完成记录不受影响。
- 如果确实想强制重跑，可以取消勾选“跳过当前规则已处理”。
- 规则记录随“导出标题备份”一起导出，导入时核对账号和规则标识。

旧版V0.1/V0.2没有记录当时采用的规则，因此不能可靠地将旧日志自动归到当前规则。升级后保留旧标题恢复记录，但规则去重从新版实际处理记录开始。新版本不会因为猜测旧规则而误跳过聊天。

## 推荐：使用本机 Codex CLI，不填云端 API Key

链路为：**插件读取正文节选 → 本机HTTP桥接 → `codex exec` → 标题建议 → 用户预览 → 插件写回。**

Windows 可双击本目录 `双击启动命名服务.cmd`，保持窗口打开；启动脚本优先使用明确设置的 CLI 路径、系统路径，再尝试查找本机 Codex 桌面版安装目录。服务重启后需要在配对页复制新配对码。助手里的“检查连接”只验证本机服务和配对，不调用模型，也不能证明 Codex 已登录；真实生成成功后才标明最近一次调用成功。连接状态不是持续监控。

升级自 v0.2 时，保留原浏览器扩展目录和 ID，不卸载扩展。旧日志可用于恢复，但不含当时规则，不能自动归为某规则已处理；旧版已生成的建议也没有规则标记，需按当前规则重新生成。升级前导出标题备份，必要时核对未完成操作。

1. 确保本机已安装 Codex CLI 并登录。可以用 `codex login status` 查看。V0.2在本机实测的版本为 `0.165.0-alpha.1.2`，认证方式为 ChatGPT。
2. 运行本目录的 `启动Codex命名服务.ps1`，或在本目录直接运行：

   ```powershell
   node .\local-codex\server.mjs
   ```

   如果 PowerShell 策略不允许运行 `.ps1`，使用上面的 Node 命令即可，不需要修改系统策略。
3. 保留启动窗口，在浏览器打开 `http://127.0.0.1:18183/`，复制页面上本次启动的配对码。
4. 插件中展开“模型与命名规则”，选择“本机 Codex CLI”，填本机地址和配对码，点击“保存并授权本机连接”。
5. 连接 ChatGPT 标签页，扫描、选择聊天并点击“一键自动重命名”，开始前确认一次；也可先用“仅生成预览”检查结果。

已加载旧版时：先将新版文件覆盖到**原来加载扩展的同一个目录**，再在扩展管理页点击该扩展的“重新加载”，并重新打开助手操作页。不要卸载旧扩展或改用另一个目录，避免改变扩展标识或丢失恢复记录；更新前可先导出标题备份。

固定请求参数为：

```
model = gpt-6-luna
model_reasoning_effort = high
service_tier = fast
```

服务不会自动换模型或降级思考等级。`fast`表示请求的服务档位；实际服务速度、模型资格及额度由账号和服务端决定，输出中记录为 `requestedServiceTier`，不伪造“实际已获加速”的证明。高思考和快速档位是两个独立参数。

每批1–5条任务，串行执行，最长等待180秒。CLI使用已有登录状态，消耗 Codex 账号额度；它仍然会把所选正文节选发送给 OpenAI，并不是在本机运行模型，也不代表免费无限调用。CLI进程有固定启动和指令开销，逐条调用的效率可能低于直接API；批量可分摊开销。

本机桥接仅监听 `127.0.0.1`，校验来源与随机配对码，不提供任意提示词代理、任意命令或文件访问接口。配对码仅放在插件会话存储中，不导出到标题备份；服务重启后需重新配对。需要停止服务时，在启动窗口按 `Ctrl+C`。

CLI每次在独立临时目录运行，使用只读沙箱，禁用命令执行、浏览器、插件等能力，不加载用户 `config.toml`，认证仍由 CLI 自己读取。不会更改你的全局 Codex 配置或复制认证文件。使用 `--ephemeral` 不保存这次会话的 rollout；本机桥接不主动保存正文，但 CLI 的其他诊断行为仍遵循其自身实现。

若端口占用，可在启动前设置 `$env:RENAMER_PORT = '18184'`，并将插件地址同步改为新端口。工具不会结束其他占用端口的程序。

## 路线 A：配置模型 API，全自动生成一批建议

1. 在助手页面选择 ChatGPT 标签页，点击“连接当前账号”。
2. 展开“模型与命名规则”，填模型 API 地址、模型名称、API Key，然后点击“保存并授权此 API 站点”。
   - 接口兼容 **Chat Completions**。可填 `https://服务商/v1` 或完整的 `/chat/completions` 地址。
   - 不指定默认服务商和模型，也不自动创建付费账号。
   - 本地兼容服务可填写 `http://localhost:端口/v1` 或 `http://127.0.0.1:端口/v1`。
   - API Key 仅放在扩展的浏览器会话存储里，浏览器完全关闭后清除；地址、模型和规则保存在本机扩展存储中。
3. 选择时间范围和扫描数量，点击“扫描聊天”。第一次建议只扫描50条，取消不想处理的聊天。
4. 点击“仅生成预览”。工具读取当前分支的文字，长对话取开头、中段和后续消息的节选，每5条请求模型一次。界面会标明是否为节选。希望直接连续应用时，改点“一键自动重命名”。
5. 检查新标题，直接编辑不满意的结果。点击“预览并应用”，核对列表后点击“确认应用”。
6. 成功后返回 ChatGPT 刷新，检查侧边栏标题。建议先处理少量聊天，确认标题质量和账号适配再扩大批次。

默认命名规则：简短中文，优先“主题｜具体问题”，约12–28字，保留英文术语，不加日期、emoji或序号，不生成泛泛的“新聊天”“问题讨论”，不臆造结论。标题最多64个字符。

**数据流：**ChatGPT 登录网页 → 扩展内存中的正文节选 → 你配置的模型服务商 → 本地标题建议 → 用户确认 → ChatGPT 标题更新。生成建议可能产生该模型服务商的 API 费用。

## 路线 B：没有 API Key，使用现有 AI 批处理

1. 连接并扫描，选择最多10条聊天。
2. 展开“免 Key 批处理”，点击“复制命名任务”或“导出命名任务”。任务包含所选聊天的文字节选，请自行决定交给哪个 AI。
3. 将任务粘贴给你现有的 AI，让它返回规定格式的 JSON。
4. 将 JSON 粘回助手，点击“导入为标题建议”。随后和路线 A 一样预览并批量应用。

这一模式省去模型 API 配置，但“交给 AI、粘回结果”由用户完成；不会伪装成全自动 AI 命名。

## 恢复和中断处理

- 每次改名之前先持久化记录：聊天编号、账号/工作区标识、旧标题、新标题和操作状态。记录保存失败时不发出写入请求。
- 写入前再次读取当前标题。如果与预览时的原标题不一致，跳过该条并标记冲突，不覆盖你后来手动修改的标题。
- 写入只提交 `title` 字段，不提交删除、归档、项目迁移或正文修改字段。
- 写入后重新读取确认；只在读回一致时显示“已应用”。
- 断网、限流、登录失效或未知结果会暂停整批，不自动重发写入。点击“核对未完成操作”只读取服务器，判断上次到底有没有成功。
- 点击“停止”后，不再开始下一条；已经发出的单条写入会完成校验。关闭操作页不等于撤回已经发送的请求。
- 选择聊天后，点击“恢复所选的上次标题”，检查恢复预览再确认。恢复也会校验当前标题，避免覆盖后续手动改名。
- “导出标题备份”生成 JSON，包含标题和恢复记录，**不含 API Key、ChatGPT 会话凭证或正文节选**。可在同一账号/工作区导入恢复记录。建议在大批量应用前导出。
- 清除浏览器扩展数据或卸载扩展可能丢失本机记录；提前导出备份。

## 已实现与边界

已实现：分页扫描、最近30/60天或全部时间筛选、模糊标题筛选、选择一批聊天、正文当前分支解析、Codex/云端批量命名、一次确认自动生成并应用、按规则去重和完成标记、可编辑预览、免 Key 任务导出/结果导入、写前日志、写后校验、停止、恢复、未完成操作核对、标题备份和账号隔离。

限制：

- 聊天列表和更新采用网页内部 `/backend-api` 接口，不是公开的 OpenAI Conversations API。公开的 Conversations API 管理的是 API 应用的会话，不能把它直接当作网页历史聊天管理接口。
- 不保证项目内、归档、其他工作区或其他平台聊天全量可见。页面显示的是当前网页接口返回的范围，扫描完成不意味着账号全部历史都已覆盖。
- 不绕过人机验证、反爬措施、登录或账号权限；遇到403/429停止。恢复登录或等待后重新连接。
- 图片、音频和文件本体不上传给命名模型。纯图片或没有可识别文字的聊天会报错，不会根据原标题冒充正文概括。
- 超长聊天只发送节选，可能遗漏细节；错误的新标题需要在应用前修改。
- 模型是概率性输出，不保证标题质量。聊天内容作为数据处理，模型返回须与所选编号完整对应，但无法保证完全消除提示注入影响。
- 服务端没有已知可用的标题条件更新接口。写前校验可降低冲突风险，但不能消除“校验完成到提交期间被其他客户端改名”的短暂竞态。批量运行时请勿在其他设备同时改这些聊天标题。
- 不自动从网页读取或复用模型 API Key；ChatGPT 会话凭证只留在网页适配器内存里，绝不发给模型服务商。
- 不默认长期保存聊天正文。操作页关闭或重新连接后内存节选缓存清空；已复制或导出的任务由用户自行保管。
- 这是由用户启动、处理所选聊天的批量工具，不会后台监听所有新聊天自动改名。

## 平台差异与 DeepSeek 已知限制

新增平台的差异全部收敛在 `adapters/<平台>.js` 里，上层（命名规则、模型后端、写前日志、恢复、备份）完全共用。

DeepSeek 的接入方式：

- **鉴权**：读取网页自己写入的 `localStorage.userToken`，在 DeepSeek 页面内发起同源请求。不读取 Cookie 数据库、不要求复制 Token、不经过第三方服务器。
- **接口**：`/api/v0/chat_session/fetch_page` 列表、`/api/v0/chat/history_messages` 正文、`/api/v0/chat_session/update_title` 改名。
- **分页**：游标式（`lte_cursor.pinned` + `lte_cursor.updated_at`），接口不返回总数，所以界面只显示已读取条数。游标不前进时会主动停止，避免空转。
- **正文**：2026-09 起从 `content` 移入 `fragments[]`，两种形态都已兼容；思考片段（`THINK`）与工具片段（`TOOL_*`）不参与命名，避免把推理过程当成讨论内容。

需要知道的限制：

- 该平台接口在 2026 年内至少改过两次数据形态（2026-09 正文迁移、2026-10 游标布尔化）。因此**连接时会先请求一次列表做自检**，形态不符直接报错，不会带着错误假设继续写。
- DeepSeek 没有 ChatGPT 那样的工作区概念，恢复记录按单一账号维度保存。同一浏览器切换 DeepSeek 账号时不会自动隔离；每次写入前仍会重新读取当前标题，被改动过的条目会跳过而非覆盖。
- 标题长度上限暂按 64 字符（与 ChatGPT 相同）。如遇该平台截断或拒绝，会在状态列标为失败，不会静默写入。
- **Gemini** 网页端没有标题概念、**WorkBuddy** 目前只有桌面端与移动端，二者都无法用浏览器扩展介入，故不纳入支持范围。

## 结构

```
manifest.json        扩展权限和入口
background.js        点击图标打开操作页
adapters/            各平台的内容脚本，只做鉴权、取数、写回
  chatgpt.js           ChatGPT 会话连接、分页读取、校验和 title 更新
  deepseek.js          DeepSeek 同职责实现（token、游标分页、update_title）
core.mjs             当前分支解析、节选、结果校验、恢复数据模型
provider.mjs         可替换的 Chat Completions 模型请求
manager.*            批量操作界面与任务流程
tests/               隔离环境测试，不连接用户账号
validation/          测试报告与实际渲染截图
scripts/             ZIP交付打包
```

扩展无第三方运行时依赖，无需构建，加载目录即可。Codex模式额外需要 Node.js 22+ 和已登录的 Codex CLI；云端API模式不需要本机服务。浏览器测试另外需要 Playwright 与 Chromium。


单元和桥接测试使用模拟服务；浏览器测试加载实际 Manifest V3 扩展，所有 ChatGPT 和云端模型请求都被本地夹具拦截，Codex模式使用真实本机HTTP通路和模拟CLI运行器，不访问真实聊天。测试结果见 `validation/browser-report.json`。真实CLI的虚构数据实测另见 `validation/codex-live-report.json`，该实测使用账号额度。**这些检查不等于已验证你的 ChatGPT 账号当前接口兼容性。**

浏览器测试可通过 `RENAMER_TEST_CHROMIUM` 指定 Chromium 可执行文件。Playwright 可使用环境中已有的依赖，不要求为运行扩展安装它。
